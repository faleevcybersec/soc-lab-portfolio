# 05. Incident Report: Валидация детектов и симуляция постэксплуатации

## 📋 Executive Summary (Резюме для руководства)
**Дата:** 26 Октября 2026 г.
**Тип работ:** Симуляция активности злоумышленника (Purple Teaming) и валидация правил SIEM.
**Статус:** Завершено. Правила детекта работают корректно.

**Описание:** 
В рамках тестирования возможностей SIEM Wazuh была проведена серия изолированных симуляций атак, имитирующих различные этапы Kill Chain (от разведки до закрепления в системе). Целью являлось подтверждение того, что настроенные правила (включая кастомные) способны фиксировать вредоносную активность, а аналитик SOC — правильно интерпретировать полученные алерты.

## 🎯 Affected Assets (Затронутые активы)
- **Hostname:** `wazuh-server`
- **OS:** Amazon Linux 2023
- **Role:** SIEM Manager / Monitored Endpoint

## 🧩 Indicators of Compromise (IOCs)
- **IP-адрес атакующего (Kali):** `192.168.0.100` *(скрыт в целях безопасности)*
- **Учетные записи:** `fakeuser` (не существует), `hacker_test` (создан в рамках симуляции и удален).
- **Артефакты:** Модифицированный файл `/etc/crontab` (восстановлен).

## 🛡 MITRE ATT&CK Mapping
- **Credential Access:** T1110.001 (Brute Force: Password Guessing)
- **Persistence:** T1136.001 (Create Account: Local Account)
- **Command and Control:** T1105 (Ingress Tool Transfer)
- **Persistence / Execution:** T1053.003 (Scheduled Task/Job: Cron)

## 🛠 Detection & Analysis (Как сработала защита)
Симуляция показала высокое покрытие детекта:
1. **Модуль аутентификации:** Успешно зафиксировал множественные попытки подбора паролей (Rule 5710).
2. **Кастомное правило (100010):** Подтвердило свою работоспособность, перехватив запуск `curl` (T1105).
3. **Модуль FIM:** В режиме реального времени (realtime) зафиксировал изменение системного файла `/etc/crontab` (Rule 550).

## 🚑 Response & Remediation (Выполненные действия)
В рамках реагирования на смоделированные инциденты аналитиком SOC были фактически выполнены следующие шаги:
1. **Очистка учетных записей:** Учетная запись `hacker_test` удалена из системы командой `userdel -r`.
2. **Восстановление конфигурации:** Вредоносная запись удалена из планировщика `/etc/crontab`.
3. **Верификация:** Повторная проверка логов подтвердила отсутствие вредоносных артефактов.

## 💡 Recommendations (Рекомендации по итогам тестирования)
1. **Снижение поверхности атаки:** Отключить аутентификацию по паролю в SSH, перейдя только на ключи (`PasswordAuthentication no`).
2. **Защита от брутфорса:** Внедрить Fail2Ban для автоматической блокировки IP-адресов после серии неудачных попыток.
3. **Контроль целостности:** Добавить в мониторинг FIM дополнительные критически важные директории (например, `/root/.ssh/authorized_keys`).
