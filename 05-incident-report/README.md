# 05. Incident Report: Обнаружение комплексной атаки (Kill Chain)

## 📋 Executive Summary (Резюме для руководства)
**Дата инцидента:** 26 Октября 2026 г.
**Критичность:** Высокая (High).
**Статус:** Закрыт (Contained & Remediated).

В ходе мониторинга событий информационной безопасности (SIEM Wazuh) была выявлена подозрительная активность на сервере `wazuh-server`. Злоумышленник предпринял попытку подбора паролей (Brute-force), после чего скомпрометировал систему, создал теневую учетную запись и установил задачу в планировщик `cron` для закрепления в системе (Persistence). Благодаря правильно настроенным правилам детекта, инцидент был локализован до нанесения существенного ущерба.

- **Hostname:** `wazuh-server`
- **OS:** Amazon Linux 2023
- **Role:** SIEM Manager / Monitored Endpoint

## 🧩 Indicators of Compromise (IOCs)
- **IP-адрес атакующего:**  *(скрыт в целях безопасности)*
- **Скомпрометированные/созданные учетные записи:** `fakeuser` (попытка), `hacker_test` (успешно создан).

## 🛡 MITRE ATT&CK Mapping
- **Initial Access:** T1110.001 (Brute Force: Password Guessing)
- **Persistence:** T1136.001 (Create Account: Local Account)
- **Execution / Persistence:** T1053.003 (Scheduled Task/Job: Cron)
- **Command and Control:** T1105 (Ingress Tool Transfer)

## 🛠 Detection & Analysis (Как сработала защита)
Инцидент был выявлен благодаря кастомным настройкам Wazuh:
1. **Wazuh Agent** на сервере успешно собирал логи `auth.log`, `journald` и отслеживал изменения файлов (FIM).
2. **Кастомное правило (100010)** позволило зафиксировать факт запуска `curl`, который используется злоумышленником.
3. Встроенный модуль **FIM (Rule 550)** в режиме реального времени зафиксировал изменение `crontab`.

## 🚑 Response & Remediation (Реагирование и устранение)
Аналитиком SOC были выполнены следующие действия:
1. **Изоляция:** IP-адрес атакующего заблокирован на межсетевом экране.
2. **Очистка:** Учетная запись `hacker_test` удалена (`userdel -r hacker_test`).
3. **Устранение:** Вредоносная запись удалена из файла `/etc/crontab`.
4. **Верификация:** Проверено отсутствие других аномалий в логах.

## 💡 Recommendations (Рекомендации для предотвращения)
1. **Отключить вход по паролю:** Настроить аутентификацию по SSH-ключам и запретить вход по паролю (`PasswordAuthentication no`).
2. **Внедрить Fail2Ban:** Установить утилиту, которая будет автоматически блокировать IP после N-го количества неудачных попыток входа.
3. **Ограничить права sudo:** Настроить политики `sudoers` (Principle of Least Privilege), чтобы обычные пользователи не могли выполнять любые команды от имени `root`.
